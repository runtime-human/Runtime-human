# Open-source система

## Цель

Open source — самостоятельный карьерный и предпринимательский путь, а не декоративный счётчик stars.

## Состояние проекта

- code quality;
- readiness;
- documentation;
- popularity;
- users;
- stars/watchers abstracted by era;
- issues;
- pull requests;
- contributors;
- maintainers;
- stability;
- technical debt;
- releases;
- governance;
- sponsors/funding;
- community health.

## Действия

- разработать feature;
- исправить bug;
- улучшить docs;
- выпустить release;
- triage issues;
- review PR;
- привлечь contributors;
- модерировать community;
- искать sponsors;
- создать paid support или hosted product;
- передать ownership.

## Community simulation

Contributors являются NPC или агрегированными background participants. Важные maintainers получают стабильные PersonId, отношения и narrative memory.

Community health зависит от:

- скорости ответов;
- качества документации;
- governance;
- code of conduct events;
- стабильности API;
- сложности входа;
- reputation maintainer.

## Пути развития

```text
library → popular project → ecosystem standard
open source → support/SaaS → company
open source → fame/conferences → Top Programmer
open source → burnout/conflict → transfer or decline
```

## Риски

- maintainer burnout;
- abandoned issues;
- hostile contributor;
- supply-chain incident;
- breaking change;
- sponsor pressure;
- fork;
- governance conflict;
- dependency obsolescence.

## Историчность

Механики популярности и распространения адаптируются к эпохе: BBS, mailing lists, SourceForge-подобные площадки, Git hosting и современные community platforms представлены через нейтральные или вымышленные интерфейсы.

## Монетизация

Внутриигровая монетизация open source относится к жизни персонажа, а не к реальным платежам игры. Возможны donations, sponsorship, consulting, dual licensing и hosted service в упрощённой модели.
