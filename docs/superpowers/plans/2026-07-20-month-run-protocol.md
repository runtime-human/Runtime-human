# MonthRun Protocol Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement a pure versioned MonthRun state machine with self-verifying checkpoints, deterministic suspend/resume, idempotent decision handling and crash-boundary equivalence tests.

**Architecture:** Contracts live in `game-schema`; canonical snapshotting, checkpoint hashing, transitions and the bounded runner live in `game-core`. A test-only in-memory harness proves command receipts and restore semantics without introducing persistence infrastructure.

**Tech Stack:** TypeScript 7, Vitest 4, existing canonical JSON/SHA-256/Xoshiro utilities, pnpm 11; no new runtime dependency.

## Global Constraints

- No SQLite, Tauri IPC, gameplay provider, UI, timer, retry, lease or background task in PR #17.
- No production code before its failing test.
- All expected failures are typed results; only exhaustive-unreachable defects may throw.
- Accepted transitions create immutable checkpoints, increment revision once and link hashes.
- Duplicate dispositions return the original checkpoint unchanged and consume no RNG.
- Existing imports of `AuthoritativeJsonValue` from `game-core` remain source-compatible.
- Exact repository gates remain mandatory: `pnpm check:fast` and `pnpm verify`.
